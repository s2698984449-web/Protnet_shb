# CRML 架构设计

## 核心问题

### 1. 什么是"关系"？

```
ProtoNet 的关系定义:

  Prototype:  p_c = mean(所有 class=c 的 support 特征)

  Relation:   r_i = R(q_i, p_c) = -||q_i - p_c||²   (欧氏距离)

  或用 cosine:
              r_i = cos(q_i, p_c)

关系 = query 到各 prototype 的"距离分布"
```

### 2. 为什么跨域不一致？

```
Domain A 的"划痕":
  q_A → 特征 [0.8, 0.2, 0.5, ...]
  p_A_scratch → [0.7, 0.3, 0.4, ...]
  距离 d_A = ||q_A - p_A_scratch|| = 0.15  ✓ 小

Domain B 的"划痕":
  q_B → 特征 [0.1, 0.9, 0.2, ...]  ← 完全不同的向量空间！
  p_B_scratch → [0.2, 0.8, 0.3, ...]
  距离 d_B = ||q_B - p_B_scratch|| = 0.15  ✓ 小

但是！混合训练时:
  q_A 与 p_B_scratch 的距离 d_AB = 很大  ✗ 不一致！
```

### 3. 根因

```
问题本质: 不同域的特征空间没有对齐

传统方法试图对齐特征空间 (Feature Alignment):
  f(q_A) ≈ f(q_B)  ← 需要翻译器，容易失真

CRML 的思路: 只对齐"相对关系" (Relation Alignment):
  f(q_A) - f(p_A) ≈ f(q_B) - f(p_B)  ← 不要求特征相同，只要求关系结构相同
```

## CRML 核心思想

### 1. 关键洞察

```
不要求:
  f(q_A) ≈ f(q_B)  (特征对齐)

只要求:
  f(q_A) - f(p_A) ≈ f(q_B) - f(p_B)  (相对位移一致)

类比:
  A 说"猫比狗大"  ← 特征值可能完全不同
  B 说"猫比狗大"  ← 但"谁大谁小"的关系是一样的

CRML 学的是: "猫>狗" 这种关系，而不是具体的数值
```

### 2. 数学表达

```
同类样本的 Relation 应该集中:

  对于 label=c 的所有 query:
    r_i[c] = -||q_i - p_c||²  (i = 1, 2, ..., N_c)
    
  要求: Var(r_i[c]) → 0

梯度方向:
  ∂L_rc/∂emb = 2×(r-μ)×(q-p)
  
  含义:
    - 如果同类 r 分散 → 方差大 → 梯度大
    - → encoder 被迫调整，让同类关系更集中
```

## 为什么 CRML 有效？

### 1. 理论直觉

```
前提: 如果同类缺陷在语义上有共性，
      那么这个共性一定反映在特征空间的某种结构上

观察: 跨域时特征值不同，但结构可能相似

CRML 的假设:
  划痕:  边缘突起的结构 → 特征梯度在某方向大
  裂纹:  线性断裂结构 → 特征梯度在另一方向大

即使:
  Domain A: 划痕 → [0.8, 0.2, ...]
  Domain B: 划痕 → [0.1, 0.9, ...]

结构上:
  ∂特征/∂位置 的模式可能相同 → 梯度方向相似 → 关系相似
```

### 2. 类比理解

```
传统方法 (特征对齐):
  学一个"翻译器"，让 A 说的话 B 也能听懂
  问题: 如果 A 和 B 说的是完全不同的语言，翻译器会失真

CRML (关系对齐):
  不要求 A 和 B 说同样的话
  只要求 A 和 B 吵架时"结论的胜负关系"一致
  谁对谁错不重要，重要的是"关系结构"不变
```

## 与现有架构的关系

### 现有架构

```
multi_domain_episode.py
    └── MultiDomainEpisodeSampler.sample()
        └── 从单一产品采样 support + query

multi_domain_model.py
    └── MultiDomainPretrainModel
        └── encode_with_product(img, cond, pid) → emb

train_meta.py
    └── proto_loss() → CE Loss
```

### CRML 扩展

```
multi_domain_episode.py
    ├── MultiDomainEpisodeSampler (原有)
    └── CrossDomainEpisodeSampler (新增)
        ├── 跨域/同域判断
        ├── 域对采样
        └── 返回 is_cross_domain 标志

train_meta.py
    ├── proto_loss() → L_ce (原有)
    ├── relation_consistency_loss() → L_rc (新增)
    └── total_loss = L_ce + λ × L_rc
```

## 关键设计决策

### 1. 为什么跨域时不要求 defect 类型对应？

```
MVTEC cable: [断路, 弯曲, 锡球, 扎伤, 错位]
GC10 steel:  [冲孔, 焊缝, 月牙弯, 水斑, 油斑]

如果我们强制 "断路" ↔ "冲孔" 对应:
  - 需要人工定义跨域标签映射 (不可行)
  - 不同人对"语义相似"的定义不同

CRML 的做法:
  - 在 episode 内，标签就是 [0, 1, 2, 3]
  - 模型学习: "如何从 support 建立判别关系"
  - 迁移时: 只要新域也有"划痕-like"的缺陷，就能泛化
```

### 2. 为什么用方差而不是对比学习？

```
对比学习需要:
  - 正样本对 (同 label 的特征应该接近)
  - 负样本对 (不同 label 的特征应该远离)

问题:
  - 跨域时正样本的特征空间本身不对齐
  - 强制拉近会损害有用的 domain-specific 信息

方差的好处:
  - 不要求特征接近，只要求"关系分布"集中
  - 更宽松，更安全
  - 计算简单
```

### 3. 权重调整的直觉

```
同域 episode:  关系本来就一致 → λ 小 (0.5)
跨域 episode:  关系不一致 → λ 大 (1.5)

原因:
  - 如果所有 episode 都用同样的 λ，模型会:
    1. 主要优化容易的同域 episode
    2. 忽略难优化的跨域 episode
    
  - 放大跨域权重，强迫模型关注跨域一致性
```
