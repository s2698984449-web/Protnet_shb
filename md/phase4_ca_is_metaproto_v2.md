# CA-IS-MetaProto: 面向工业结构化域变化的上下文自适应元原型方法

> **Context-Adaptive Industrial Shift-aware Meta Prototype Learning**
>
> 上下文自适应的工业域变化感知元原型学习方法

---

## 一、为什么需要这个方法

### 1.1 工业缺陷检测中的实际问题

工业产线在实际生产中经常面临以下挑战：

| 场景 | 具体描述 | 核心需求 |
|:----:|----------|----------|
| 新产品上线 | 已有产品 A 的模型需要迁移到新产品 B | 仅 5 个标注样本即可部署 |
| 材料变更 | 同一类部件，材料由铝合金替换为钛合金 | 模型无需重新训练 |
| 产线环境变化 | 光照、相机角度、采集环境改变 | 模型稳健地继续工作 |

**核心痛点**：传统监督学习方法依赖大量标注数据，而工业现场往往只有少量标注样本可用。

### 1.2 现有方法及其不足

| 方法 | 核心原理 | 优点 | 不足 |
|:----:|----------|------|------|
| **ProtoNet**<br>原型网络 | 给定少量支持样本，计算每个类别的平均特征作为原型，测试样本与原型距离最近的类别即为预测结果 | 简单高效，适合少样本场景 | 把所有任务一视同仁，不区分工业场景的具体特征 |
| **MAML**<br>模型无关元学习 | 在多个任务上学习一个好的初始化参数，使模型能通过少量梯度更新快速适应新任务 | 理论上能适应多种任务 | 需要内循环优化（即在新任务上多次更新参数），部署成本高，不适合工业快速上线 |
| **Domain Generalization**<br>域泛化 | 学习跨多个源域不变的特征表示，使模型能泛化到未见过的目标域 | 不需要目标域数据 | 通常不考虑任务级元数据，无法利用工业现场的结构化信息 |

**综合不足**：

现有方法要么忽略工业场景的特有信息，要么引入复杂的训练机制导致部署困难。我们需要一种既能利用工业上下文信息，又保持快速部署能力的方法。

### 1.3 工业数据的结构性特征

工业域变化并非随机，而是由可解释的因素驱动：

| 变化维度 | 英文术语 | 典型示例 | 影响特征 |
|:--------:|----------|----------|----------|
| 部件变化 | Component Shift | 叶片 → 涡轮盘 | 几何结构、ROI 位置 |
| 材料变化 | Material Shift | 铝合金 → 钛合金 | 表面纹理、反射特性 |
| 环境变化 | Environment Shift | 工厂光照 → 自然光 | 亮度、色温、对比度 |
| 缺陷变化 | Defect Shift | 划痕 → 凹坑 | 缺陷形态、类内方差 |

**关键发现**（基于我们已有的实验）：

在航空叶片的 ProtoNet Baseline（exp08，3-seed 终评 85.2%）中，跨域精度从域内融合的 ~88% 下降到 domain_3（试件 20-26 holdout）的 85.2%。进一步分析 exp11（v5 supcon 单 seed 98.33% eval / 90.67% domain_3）发现，**backbone 质量提升能在 domain_3 上带来 +5.5pt，但单 seed 方差仍达 ±12.5%**，主要来自不同试件（specimen 20-26）的材料/光照差异。

如果能提前知道是什么因素在变化，就可以针对性调整模型。

| 模块 | 阶段 | 依赖输入 | 训练方式 | 计算开销 |
|:----:|:----:|----------|----------|:--------:|
| Context Encoder | Phase 1 (Meta 元训练) + Phase 2 (推理) | source/target Metadata | 在 Meta 训练中端到端学习 | < 1 ms |
| Shift Identification | Phase 2 (推理) | 融合 m + 视觉特征 | 单独分类器, Phase 1 训练 | < 1 ms |
| Context Selector | Phase 2 (推理) | ΔT + 视觉特征 | 门控网络, Phase 1 训练 | < 1 ms |

**关键点**：

| 项目 | 说明 |
|------|------|
| 三个模块都是在 Phase 1 (Meta 训练) 完成学习 | 不是 Phase 2 现造 |
| 三个模块都是在 Phase 2 (推理) 实时调用 | 每次新产品上线时用一次 |
| Context Encoder 训练时用强监督（知道真实变化） | Shift ID 训练时用 4 维 classification loss |
| Context Selector 训练时端到端 | 用最终的 query 损失反传 |

### 2.6 关键概念澄清：什么是"目标域数据"

> **目标域数据 = 元测试数据 (meta-test data) = holdout 域数据 = 推理时的新产品数据**

这是**容易混淆的关键问题**，下面用**三个对照表**明确：

#### 2.6.1 三层数据集对比

| 层级 | 英文术语 | 含义 | 数据划分 | 用途 |
|:----:|----------|------|----------|------|
| **源域数据** | Source Data | 训练 backbone 时用的所有数据 | 全部真实叶片 + BladeSynth + AeBAD | Phase 0 预训练 |
| **元训练数据** | Meta-train Data | Meta 训练阶段采样的任务来源 | domain_0, domain_1, domain_2 | Phase 1 元训练 |
| **目标域数据** | Target Data = Meta-test Data | 模型真正要解决的问题 | domain_3 (试件 20-26) | Phase 2 推理, 评估泛化 |

#### 2.6.2 目标域 vs 元训练域 的具体例子

| 维度 | 元训练域 (meta-train) | 目标域 (target) |
|:----:|----------------------|----------------|
| 英文 | meta-train domains | target domain / meta-test domain |
| 在我们的实验 | domain_0, domain_1, domain_2 | domain_3 |
| 数据 | 试件 0-19 部分 | 试件 20-26 |
| 角色 | 提供"如何学习"的多样任务 | 仿真"新产品上线" |
| 可见性 | 模型训练时反复使用 | 训练时**完全不可见** |
| 评估 | eval_acc (训练域随机任务) | domain_3_acc (真正泛化指标) |

#### 2.6.3 相邻概念辨析

| 概念 | 含义 | 在我们的实验 |
|------|------|-------------|
| Target Domain | 元学习要泛化的目标域 | domain_3 (试件 20-26) |
| Meta-train Domain | 提供元训练任务的域 | domain_0,1,2 |
| Meta-test Domain | 写作中常和 target 等价 | = target domain |
| Source Domain | 预训练来源（Phase 0） | 真实叶片 + BladeSynth + AeBAD |
| Test Set | 监督学习中验证模型的子集 | 我们实验中是 domain_3 |
| Holdout | 始终留出的测试集 | 就是 domain_3 |
| OOD (Out-of-Distribution) | 训练未见的分布 | target domain = domain_3 = OOD |

**结论**：

| 你的问题 | 回答 |
|----------|------|
| "目标域数据" 等于什么？ | = 元测试数据 = holdout 域 = 推理时的新产品数据 |
| "目标域数据" 是元训练数据吗？ | **不是**。元训练数据是 domain_0,1,2；目标域是 domain_3 |
| "目标域数据" 训练时能看到吗？ | **完全不能**。这是 Few-shot 评估泛化能力的前提 |
| "目标域数据" 哪里来？ | 真实场景中的新产品 / 新试件 / 新产线 |
| 论文里"target"和"meta-test"是同一概念吗？ | **是的**，两个术语在不同文献中常混用，我们统一用"目标域" |

#### 2.6.4 三个阶段中"目标域数据"的角色

| 阶段 | 目标域数据是否被使用 | 用途 |
|:----:|:-------------------:|------|
| Phase 0 预训练 | ❌ 不使用 | 预训练只用源域数据 |
| Phase 1 元训练 | ❌ 不使用 | 元训练只用 meta-train 域 (domain_0,1,2) |
| Phase 2 推理 / 评估 | ✅ **使用** | 这是 Phase 2 唯一会接触目标域数据的阶段 |

**这就是为什么 Phase 2 才有"变化识别 / 上下文选择 / 元数据融合"三个模块**：

- 训练阶段根本看不到目标域数据，自然无法识别"目标域相对训练域有什么变化"
- 只有在 Phase 2 部署时，**第一次接触到目标域数据**，才能判断 ΔT 才能算 w 才能调原型
- 这三个模块是**从"训练完成"到"成功适配目标域"之间的桥梁**

### 4.2 三个核心模块

| 模块 | 输入 | 输出 | 核心作用 |
|:----:|------|------|----------|
| **Module 1**<br>Shift Identification<br>（变化识别） | 源域元数据 + 目标域元数据 + 视觉特征 | 变化类型标识 ΔT ∈ {ΔC, ΔM, ΔE, ΔD} 及其组合 | 明确当前任务面临的主要挑战 |

| **Module 3**<br>Adaptive Prototype<br>（自适应原型） | 支持样本特征 + 上下文权重 w + 变化类型 ΔT | 上下文感知的类别原型 P_c | 针对不同变化类型调整原型构建策略 |

### 4.3 与现有 Baseline 方法对比

| 方法 | 上下文利用 | 变化识别 | 部署速度 | 工业适配 |

| Domain Generalization | 无 | 隐式 | 快 | 一般 |
| **方案 C 当前最优（exp14）** | **无** | **无** | **快** | **强** |
| **CA-IS-MetaProto（本文）** | **选择性利用** | **显式识别** | **快** | **强** |

**关键差异**：

| 对比对象 | 我们的差异化优势 |
|----------|------------------|
| 相比 exp14（trim_mean + mahal） | 我们引入 Shift ID 和 Context Selection，对工业 Metadata 的利用更智能 |

|:------:|------|------|
| **创新 1**<br>工业域变化的结构化分析 | 现有方法把工业域变化视为整体分布差异，忽略了变化的可解释性 | 系统定义 Component / Material / Environment / Defect 四维变化，并分析不同维度对 Few-shot 泛化的差异化影响 |
| **创新 2**<br>Shift-aware Context Selection | 现有方法要么忽略工业上下文，要么简单拼接所有上下文，无法处理不可靠或缺失的上下文 | 根据识别出的变化类型，动态选择应该信任的工业上下文，对错误或缺失的 Metadata 具有鲁棒性 |
| **创新 3**<br>Shift-aware Adaptive Prototype | 传统 ProtoNet 用固定方式构建原型，无法适应不同类型的工业变化 | 根据变化类型调整原型构建策略，例如 Component 变化时关注局部特征聚合，Material 变化时关注纹理特征差异 |

## 九、与现有成熟框架的详细对比

### 9.1 对比 ProtoNet + Task Embedding

| 对比维度 | ProtoNet + Task Embedding | CA-IS-MetaProto（本文） |
|:--------:|---------------------------|--------------------------|
| 上下文处理 | 将所有 Metadata 拼接为一个向量 | 识别变化类型，根据类型选择性信任不同 Metadata |
| 错误鲁棒性 | 错误 Metadata 会污染原型 | 对错误 Metadata 具有鲁棒性 |
| 可解释性 | 权重变化难以分析 | 可分析权重变化与变化类型的对应关系 |
| 工业适配 | 要求所有 Metadata 完整 | 支持 Metadata 部分缺失场景 |

### 9.2 对比 MAML / ANIL

| 对比维度 | MAML / ANIL | CA-IS-MetaProto（本文） |
|:--------:|-------------|--------------------------|
| 训练机制 | 需要内循环优化 | 不需要内循环优化 |
| 部署速度 | 需要在新任务上多次前向+反向传播 | 只需 K 个支持样本即可构建原型 |
| 上线时间 | 数小时到数天 | < 1 小时 |
| 可解释性 | 原型可解释 | 原型可解释，便于工程师理解 |
| 已有结果 | exp02: 53%, exp04: 68% | exp14: 98.4% |

### 9.3 对比 Domain Generalization 经典方法

| 对比维度 | Domain Generalization | CA-IS-MetaProto（本文） |
|:--------:|----------------------|--------------------------|
| 核心思想 | 学习域不变特征 | 充分利用工业元数据辅助适应 |
| 目标域数据 | 不需要目标域数据 | 可利用少量目标域数据 + Metadata |
| 元数据利用 | 不利用 | 充分利用 |
| 精度表现 | Metadata 完整场景下精度有限 | Metadata 完整场景下精度更高 |

## 十一、术语解释表

| 中文术语 | 英文术语 | 解释 |
|:--------:|----------|------|
| 少样本学习 | Few-shot Learning | 只有少量标注样本时进行模型训练 |
| 元学习 | Meta-learning | 学习"如何学习"，使模型能快速适应新任务 |
| 原型 | Prototype | 类别在特征空间中的代表向量，通常用支持样本的均值 |
| 原型网络 | ProtoNet | 用类别原型做分类的 Few-shot 方法 |
| 模型无关元学习 | MAML | 通过内循环适应新任务的元学习方法 |
| 简化版 MAML | ANIL | MAML 的简化版，只微调最后一层 |
| 域变化 | Domain Shift | 训练数据与测试数据的分布差异 |
| 域泛化 | Domain Generalization | 让模型在未见过的目标域上表现良好 |
| 任务 | Episode | Few-shot 中的一个任务，包含支持集和查询集 |
| 支持集 | Support Set | 包含标注样本的集合，用于构建类别原型 |
| 查询集 | Query Set | 待预测的样本集合 |
| N类K样本 | N-way K-shot | 任务包含 N 个类别，每类 K 个标注样本 |
| 工业元数据 | Industrial Metadata | 工业生产过程中的结构化信息（部件、材料、工艺等） |
| 部件变化 | Component Shift | 工业产品的组成结构差异 |
| 材料变化 | Material Shift | 工业产品使用的原材料差异 |
| 环境变化 | Environment Shift | 光照、温湿度等采集条件差异 |
| 缺陷变化 | Defect Shift | 工业产品中的瑕疵类型差异 |
| 变化识别 | Shift Identification | 识别当前任务与训练数据的主要差异维度 |
| 上下文选择 | Context Selection | 根据变化类型选择应信任的工业上下文 |
| 自适应原型 | Adaptive Prototype | 根据上下文信息调整的类别原型 |
| 上下文污染 | Context Corruption | 人为提供错误的 Metadata，测试模型鲁棒性 |
| 跨域 | Cross-domain | 训练与测试来自不同分布 |
| 骨干网络 | Backbone | 特征提取的基础网络（如 YOLO26、ResNet） |
| 注意力模块 | CBAM | 通道+空间注意力机制，用于增强特征 |
| 特征提取器 | Feature Extractor | 将原始图像转换为特征向量的网络 |
| 嵌入 | Embedding | 将高维数据映射到低维特征空间 |
| 马氏距离 | Mahalanobis Distance | 考虑特征方差的距离度量，比欧氏距离更鲁棒 |
| 截尾均值 | Trim Mean | 去除极端值后的均值，减少异常值影响 |
| 内循环 | Inner Loop | 元学习在新任务上的快速适应过程 |
| 外循环 | Outer Loop | 元学习在多个任务间的元参数更新 |
| 制造执行系统 | MES | 工业生产管理系统，记录生产过程信息 |
| 企业资源计划 | ERP | 企业资源管理系统 |
| 物料清单 | BOM | 产品的材料构成清单 |
| YOLO26 | YOLO26 | YOLO 系列目标检测第 26 代，本项目用作特征提取 |
| SupCon | Supervised Contrastive | 有监督对比损失，利用标签信息提升特征质量 |
| 投影维度 | proj_dim | 投影头的输出维度（如 64d） |
| 域 Hold-out | Domain Hold-out | 把某个域完全作为测试集，验证跨域泛化 |
| 3-seed 终评 | 3-seed final eval | 用 3 个不同随机种子训练并取均值，评估稳定性 |
