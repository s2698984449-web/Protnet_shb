# 现状梳理：框架、算法、瓶颈、调用与数据

日期：2026-11-04。本文回答：现在有什么、怎么跑、效果如何、问题在哪、钢板领域还能用哪些更完整的开源集。

---

## 1. 一句话结论

当前 CSPD 是「冻结 ImageNet 骨干 + 空间 ProtoNet + 可选工况 FiLM + 按类策略 + 可选掩码加权」的通用训练框架。链路能训，但在真正跨域/小样本意义上**还没有做出有效增益**。

- NEU 同分布切图上：准确率约 **0.97**，策略几乎多余。
- MVTec 螺丝难例上：准确率约 **0.23～0.35**（5 类乱猜 0.2），全开不优于只训投影，且严重过拟合。
- 钢板跨域主实验（NEU↔GC10、GC10 新类）**尚未按正确协议跑起来**。GC10 本地有，但还没整理进类别文件夹配置。

主瓶颈不在“策略头写不出来”，而在：**评估协议、区域信息、工况信号、主数据还没对齐钢板任务**。

## 2. 当前框架（代码结构）

```text
config/cspd.yaml          唯一正式配置（路径 + 旁路 + 超参）
config/cspd_test.yaml     冻结对照配置

cspd/
  backbone.py             SpatialResNet18（可冻）
  condition.py            MLPEncoder + FiLM
  condition_io.py         六槽工况 + 缺测掩码 + 亮度 CSV
  annotate.py             掩码、高斯权重、质心
  policy.py               按类输出 g / alpha / gate / tau
  model.py                检测器前向、内循环、打分
  data.py                 通用类别文件夹 episode
  runtime.py              构模、损失、评估、输出
  restore.py              还原图目录约定（扩散不在此训）

scripts/
  split_class_folder.py   通用 train/val/test 拆分
  load_data.py            检查数据
  train_cspd.py           训练 + 早停(val) + best/last
  infer_cspd.py           测试集评估

data_proc/
  compute_illumination.py 亮度标准与偏移 CSV
```

数据约定（与数据集名字无关）：

```text
<split_root>/<类名>/...图片
可选：
  condition_file          JSON 工况
  illumination_manifest   亮度 CSV
  mask_root + mask_pattern 掩码
  restored_root           还原图平行目录
```

## 3. 当前算法（前向与学习）

### 3.1 前向

1. 原图、可选还原图过冻结 ResNet18，取 layer3/layer4。
2. 1×1 投影到 128 维。
3. 还原支路特征用工况槽位做 FiLM；缺测维乘 0。
4. 策略只看**该类支持图**，吐出：
   - `g`：信还原/工况支路的比例
   - `alpha`：细/粗尺度权重
   - `gate`：通道敏感度
   - `tau`：距离温度
5. 支持集按类建空间原型；有掩码时对缺陷区域做高斯加权。
6. 查询图算到各类原型的负欧氏距离图 → top-k 均值得类别；峰值得位置。

### 3.2 损失与更新

| 项 | 位置 | 作用 |
| --- | --- | --- |
| 内循环支持 CE | `model.forward` | 只临时改 `proj3/proj4` 副本 |
| 外循环查询 CE | `train_cspd.py` | AdamW 更新投影初值、编码、FiLM、策略 |
| 定位 L1 | 峰值 vs 掩码质心 | `location_loss_weight>0` 且有掩码才生效 |

策略**没有**单独奖励，梯度全部来自查询分类（加可选定位）。

### 3.3 现在实际“开着什么”

以当前 `config/cspd.yaml` 为准：

| 开关 | 现状 |
| --- | --- |
| 数据 | 指向螺丝 `fewshot_v2`，不是钢板主线 |
| 六槽工况 | 无 `condition_file`；无亮度 CSV；仅 `illuminance` 用灰度补位 |
| 掩码 | 螺丝 `ground_truth` 已接；钢板框未接 |
| 还原图 | `restored_root` 空 |
| 内循环 | `adapt_steps: 1` |
| 早停 | 需要 `val_dir`；螺丝已拆 val |

因此：策略/FiLM/扩散入口在架构上存在，但**有效输入大多为空或是弱补位**，功能没有真正发挥。

## 4. 怎么调用

```text
# 1) 可选：把任意类别根目录拆成 train/val/test
python scripts/split_class_folder.py --input 类别根目录 --output 输出根目录 --train 0.34 --val 0.33 --test 0.33

# 2) 可选：算亮度偏移
python data_proc/compute_illumination.py --input 图像目录 --output 结果目录 --group all

# 3) 改 config/cspd.yaml 的绝对路径与旁路后检查
python scripts/load_data.py --config config/cspd.yaml

# 4) 全开训练
python scripts/train_cspd.py --config config/cspd.yaml

# 5) 只训投影对照
python scripts/train_cspd.py --config config/cspd_test.yaml

# 6) 推理用 best
python scripts/infer_cspd.py --config config/cspd.yaml --ckpt output/<exp_name>/best.pt
```

输出目录：`output/<exp_name>/`  
含 `config.yaml`、`structure.txt`、`data_summary.json`、`train.log`、`best.pt`、`last.pt`。

## 5. 已有实验结果（效果如何）

### 5.1 NEU-CLS（同 6 类，不同图）

| 运行 | 设定 | 测试准确率 | 解读 |
| --- | --- | --- | --- |
| `NEU-CLS_v1` | 全开，20 iter | **0.976** | 太容易，策略多余 |
| `NEU-CLS_base20` | 只投影 | **0.968** | 与全开差约 1 张图 |

结论：同分布分类已饱和，**不能**用来证明跨域或策略有效。

### 5.2 MVTec 螺丝（5 缺陷类，难例探针）

| 运行 | 设定 | 早停选出 | 选出时 acc | 过程最高 acc | 训练后期 |
| --- | --- | --- | --- | --- | --- |
| `SCREW_base_v2` | 只投影 | iter 35 | 0.272 | ~0.352 | 训 acc→1.0，测 loss↑ |
| `SCREW_v2` | 全开 | iter 10 | 0.232 | ~0.344 | 同上，过拟合更明显 |

5 类随机猜 ≈ 0.20。全开没有稳定超过只投影。  
公开量级参考（协议不同，只看量级）：PatchProto 螺丝 5-shot ≈ 0.42；掩码后再 Proto ≈ 0.74。

结论：难数据上**优化模块未带来可用增益**；当前配置仍指着螺丝，钢板主线未开跑。`RUN_v1` 尚无完整训练日志。

## 6. 问题在哪（瓶颈拆开）

### 6.1 协议问题（最优先）

| 现况 | 问题 |
| --- | --- |
| NEU `domain_0/1/2` | 同 6 类切图，不是新类、不是新域 |
| 螺丝实验 | 难，但不是钢板主叙事 |
| GC10 | 本地有框，却未进类别文件夹 + 跨域/新类协议 |

没有正确协议，精度高低都解释不清。

### 6.2 数据与标注

| 项 | 现状 |
| --- | --- |
| NEU-CLS | 有；无框无掩码 |
| NEU-DET | **本地缺失**；有框，应补 |
| GC10-DET | **本地有**（1–10 类目录 + 标注）；未整理进当前 loader 主实验 |
| 真实工况记录 | 无；六槽几乎全缺测 |
| 配对光照 | 无；扩散不能正训 |

### 6.3 算法与模块发挥度

| 模块 | 发挥度 | 原因 |
| --- | --- | --- |
| 空间 ProtoNet | 中 | 整图原型在细缺陷上被背景冲淡 |
| 掩码高斯原型 | 低→刚接通 | 钢板框未用；螺丝上全开仍不涨 |
| 策略 | 低 | 输入弱，学不到检测先验 |
| FiLM/六槽 | 低 | 缺测；补位亮度≠产线工况 |
| 内循环 | 负向风险 | 小数据上助记训练集 |
| 还原图/扩散 | 未用 | `restored_root` 空 |

### 6.4 工程与评估

- 早停曾误用测试集；现已强制 `val_dir`。
- `eval_tasks` 过小会抖；螺丝长跑里最高 acc 和早停选出的一轮不一致。
- 配置 `exp_name` 不会自动升版，重复跑会覆盖同目录。

## 7. 更完整的数据集清单（钢板优先）

### 7.1 主线必用（钢板 / 热轧）

| 数据集 | 规模与标注 | 本地 | 用途 |
| --- | --- | --- | --- |
| **NEU-CLS** | 1800 图，6 类，图像级 | 有 | 分类基线；同分布对照 |
| **NEU-DET** | 同 6 类 + 框 | **缺，应下载** | 区域原型、定位 |
| **GC10-DET** | ~2300 图，10 类 + 框 | 有 | **跨域 / 新类主表** |
| **X-SDD** | 1360 图，7 类热轧 | 无 | NEU 补充，类更全 |
| **Severstal** | 大图，4 类，像素掩码 | 无 | 分割式区域；类体系不同 |
| **FS-ND** | NEU-DET 重构的小样本检测划分 | 无 | 与论文对齐的 few-shot 检测协议 |
| **FSC-20 / FSSD-12** | 带钢小样本分类/分割基准 | 无 | 专门 few-shot 设定 |

NEU-DET 获取（官方常用）：Google Drive / 百度盘（码常见 `pmqx`）。  
GC10：GitHub `lvxiaoming2019/GC10-DET-Metallic-Surface-Defect-Datasets`，百度盘码常见 `cdyt`；Kaggle 也有镜像。

### 7.2 扩展（第二跨域，非第一优先）

| 数据集 | 说明 |
| --- | --- |
| Magnetic Tile | 磁瓦表面，像素级，另一金属域 |
| Kolektor SDD | 本地有；电子/表面，可作附录 |
| MVTec / MVTec-FS | 多产品；螺丝难例；不当钢板主表 |
| NEU-Seg / SD-saliency-900 | 分割/显著性，服务区域头 |

### 7.3 推荐主实验表（协议）

1. **同域新类：** GC10 固定 7 类 meta-train / 3 类 meta-test（多 seed）。  
2. **跨数据集：** NEU（有框则 DET）上训 → GC10 上测。  
3. **消融：** 纯 ProtoNet / +框或掩码加权 / +策略 / +工况。  

不要再把“NEU 同 6 类切图 0.97”写成跨域成功。

## 8. 模块正确用法（钢板阶段）

建议严格按顺序，一次只开一层：

1. **整理 GC10 + 下载 NEU-DET** → 类别文件夹 + 框转掩码或框加权旁路。  
2. **`cspd_test.yaml`：冻策略、冻 FiLM，`adapt_steps=0`** → 纯空间 Proto 基线。  
3. **打开掩码/框加权 + 定位损失** → 看区域是否涨点（公开经验通常涨最多）。  
4. **再开 FiLM**（先接亮度 CSV 或真实照度）。  
5. **最后开策略**；对照冻住 vs 打开。  
6. **`restored_root` / 扩散** 等有配对光或至少有稳定校正图再上。

## 9. 和公开成熟方案的差距

成熟钢板小样本常见形态：

- 预训练特征 + ProtoNet / Matching / Relation  
- 有区域则做区域原型  
- 评估用 base/novel 或跨数据集  

你们多出来的是：**工况槽位 + 按类策略先验**。这在输入有效之前不会自动变成优势。当前相对公开方案的缺口是：

1. 还没用 GC10/NEU-DET 做标准协议；  
2. 区域头未在钢板主数据上验证；  
3. 工况仍是弱补位；  
4. 缺少与 ProtoNet/RelationNet 的同协议数字对照表。
