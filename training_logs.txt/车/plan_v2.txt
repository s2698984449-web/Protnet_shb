------------------------------------------------------------------------------
零、第一性原理
------------------------------------------------------------------------------

本质问题:
  给定极少标注（5 张/类），在未见域上做二分类（scratch vs dent）

充分条件（缺一不可）:
  1. 特征空间可分 — Holdout LogReg 足够高
  2. Meta-train 任务分布覆盖 test 域变化 — 域划分有物理/视觉意义
  3. 推理协议与训练一致 — 同类 taxonomy；ProtoNet 5-shot

失败模式:
  缺 1 → Meta 上限 = LogReg，调 iter 无效
  缺 2 → train 域内高分、test 掉回 62%（Track2 已见）
  缺 3 → intact 代理 dent，语义错（Track2 已见）

二、对抗性审查 — 3 个月最可能翻车点
------------------------------------------------------------------------------

P0 风险（必须先验证）:

  R1 CarDD 三分域差异不足（概率~70%）
    随机/image 顺序切域 → 三域同分布 → M1≈Track2
    判据: 跨域 LogReg 矩阵 mean
      >85%  → 域太像，M1 叙事弱
      65–80% → 理想 sweet spot
      <60%  → 域太散，meta-train 不迁移 test
    禁止: 用 Phase0 同一权重做 K-means 再在同一权重上评测（循环论证）
    推荐: image stem 贪心三分 或 冻结 yolo26n embedding K=3

  R2 Vehicle-level 泄漏（概率中，致命）
    CarDD 同车多图 → train 见过 test 车纹理 → M1 虚高
    必做: COCO image_id / file_name 与 test 交集=0

  R3 Phase0→Meta 接口断层（概率中）
    分类 CE vs 原型距离 目标不一致
    判据 Gate D1: LogReg vs frozen ProtoNet 5-shot gap
      gap>5% → Phase0 v4 SupCon+CE
      gap≤3% → v3 够用，推进 M1
    已有: Meta 62.5% vs LogReg 64.5% gap≈2pt（接口非主因）

P1 风险:

  R4 统计检验: test 独立 task 上界≈23，100 tasks 大量重采样
    主表仍报 100×3seed；附录 bootstrap CI + 注明独立 task 数

  R5 Protocol-C 天花板低: 若 C≈62% 且 M1≈62% → 任务本身难，改 narrative

  R6 M1 > Protocol-C → 先查泄漏/评测 bug，不可直接写进主表

三、三协议设计（论文主结构）
------------------------------------------------------------------------------

| 协议 | 问题 | Meta-train | Meta-test | 预期 | 角色 |
|------|------|------------|-----------|------|------|
| Protocol-C | 全监督上限 | — | CarDD test cls | 65–75% | 熔断 baseline |
| Protocol-M1 | 同数据集新批次 5-shot | CarDD train d0/1/2 | CarDD test d3 | 66–72% | 主 claim |
| Protocol-M2 | 产线→定损跨域 | ASDE+Kolektor | CarDD test d3 | 58–65% | 副实验 |
| Track2 | 语义错 ablation | ASDE d0 | CarDD test | 62.5%✓ | 反例 |
| Random | 随机 episodic | CarDD train 池 | CarDD test | 50–58% | 下界 |

M1 硬约束:
  train & test 均为 0_scratch vs 3_dent（真 dent，无 intact 代理）
  CarDD test 永不进 Phase0 / meta-train

M2 语义修正:
  0_scratch vs 1_defect（ASDE intact→normal 侧，CarDD dent→defect）

四、诊断门控（Gate，未通过不跑 M1 300iter）
------------------------------------------------------------------------------

Gate D1 — Phase0 接口诊断（今天，~2h）
  脚本: python scripts/diagnose_phase0_interface.py --track automotive
  输出: reports/diagnose/automotive/interface_diagnosis.json
  决策:
    gap>0.05 → 启动 Phase0 v4 SupCon+CE
    gap≤0.03 → v3 保留

Gate D2 — CarDD 域划分 + 泄漏（本周，2–3d）
  1) vehicle/image_id 与 test 零交集审计
  2) 三分域（stem 贪心 或 yolo26n K-means，非 Phase0 权重）
  3) 跨域 LogReg 6 对矩阵 + mean
  4) 每域 min(scratch,dent)≥50 ROI
  不过 → 放弃 M1 主 claim，改 M2+C 叙事

Gate D3 — Protocol-C（本周，1–2d，与 D2 并行）
  Phase0 ckpt + CarDD train 全量 2-way finetune → test
  决策:
    C<65% → 天花板 narrative
    C≥65% → M1 主实验 worth it

Gate D4 — Track2 收尾
  cmpl_eval_track2 3-seed → 坐实 62.5%

决策流:
  D1 → D2+D3 并行 → 全过 → M1 300iter + 3seed + random baseline
